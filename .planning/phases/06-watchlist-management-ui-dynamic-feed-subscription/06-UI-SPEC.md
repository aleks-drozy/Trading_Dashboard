## Interaction Contract

### Add Symbol Flow

1. User types a symbol into the Input field (placeholder: "Ticker symbol e.g. SPY").
2. Client normalises to uppercase on every keystroke (`value.toUpperCase()`).
3. User presses Enter or clicks the "+" Button.
4. **Client-side pre-validation** (before any network call):
   - Empty string: no-op (do not show error, do not call API)
   - Symbol already in local list: show inline error "Already in watchlist"
   - Fails pattern `/^[A-Z0-9.]{1,10}$/`: show inline error "Invalid ticker format"
5. **Optimistic update**: append `{ symbol, asset_type: 'stock' }` to local list immediately; clear the input field; clear any existing error.
6. **API call**: POST `/watchlist` with `{ symbol, asset_type: "stock" }`.
7. **On success**: no further action (optimistic state is correct).
8. **On failure**: roll back the optimistic entry; display inline error below the input using the server's `detail` message, or "Failed to add symbol" as fallback.
9. Error clears on the next keypress in the input or on next successful add.

### Remove Symbol Flow

1. User clicks the X button on a symbol row.
2. **Optimistic update**: remove the item from local list immediately.
3. **API call**: DELETE `/watchlist/{symbol}`.
4. **On success**: no further action.
5. **On failure**: reload full watchlist from GET `/watchlist` to restore correct server state; show a sonner toast "Failed to remove {symbol}".
6. No confirmation dialog — removal is instant. The only confirmation pattern used in this phase is the sonner toast on failure.

### Loading State

- On initial mount, sidebar shows a muted "Loading..." text (text-xs, color `#6B7280`) while GET `/watchlist` resolves.
- Once loaded, the symbol list renders. If the watchlist is empty, the empty state renders instead.

### Awaiting Data State (new symbol added)

- After a symbol is optimistically added, a small muted label "(awaiting data)" appears inline next to that symbol in text-xs `#6B7280`.
- This label is removed when the WebSocket first broadcasts a signal entry for that symbol.
- This handles Pitfall 4 from RESEARCH.md: new symbol appears in sidebar but not yet in SignalTable.

## State Diagram

```
INIT
  └─► LOADING (fetching GET /watchlist)
        └─► IDLE (list rendered or empty state shown)
              ├─► ADD_PENDING (optimistic add + POST in flight)
              │     ├─► IDLE (success)
              │     └─► ADD_ERROR (rollback + show inline error)
              └─► REMOVE_PENDING (optimistic remove + DELETE in flight)
                    ├─► IDLE (success)
                    └─► IDLE (failure: reload from server + toast error)
```

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "+" (icon-only button with aria-label="Add symbol") |
| Add input placeholder | "Ticker e.g. SPY" |
| Sidebar section heading | "Watchlist" |
| Empty state heading | "No symbols" |
| Empty state body | "Add a ticker above to start tracking signals." |
| Loading state | "Loading..." |
| Awaiting data inline label | "awaiting data" |
| Inline error — duplicate | "Already in watchlist" |
| Inline error — invalid format | "Invalid ticker format" |
| Inline error — API failure (add) | Server `detail` field, or "Failed to add symbol" |
| Remove toast error | "Failed to remove {SYMBOL}" |
| Destructive confirmation | None — remove is optimistic with no confirmation dialog |

Notes:
- All copy is lowercase or sentence-case. No all-caps in body copy (column headers use uppercase only for table head labels, which is an existing pattern).
- "Ticker" is used instead of "symbol" in user-facing strings — shorter and matches trader vocabulary.

## Accessibility Contract

- Add input: `aria-label="Symbol ticker"` (label is not rendered visually; placeholder serves as hint).
- Add button: `aria-label="Add symbol"` (icon-only button must have accessible label).
- Remove button per row: `aria-label="Remove {SYMBOL}"` (e.g., "Remove SPY").
- Inline error paragraph: `role="alert"` so screen readers announce it on state change.
- Focus management: after successful add, focus returns to the input field.
- Keyboard: Enter in the input field triggers the add action (same as clicking "+").
